## §A  LOGO ASSET REPLACEMENT PLAN  (CR‑11 + CR‑14)

We received **10 PNGs** (transparent / white / light‑green; horizontal / vertical; large‑icon). Store them in `public/assets/brand/`:

```
lifehouse_color_horizontal.png   # primary nav + footer
lifehouse_color_vertical.png     # favicon base (generate 32×32)
lifehouse_color_icon.png         # mobile navbar
lifehouse_white_horizontal.png   # dark‑mode nav
lifehouse_white_icon.png         # dark‑mode mobile
lifehouse_whitepurple_horizontal.png  # hero overlay
lifehouse_lightgreen_horizontal.png   # email headers (light BG)
lifehouse_lightgreen_icon.png         # email favicon
lifehouse_color_large_icon.png        # OG‑image template
lifehouse_white_large_icon.png        # alternate OG (dark BG)
```

### A.1  Code Changes

1. **React `Logo.jsx` component** – Accept props `{variant:'color'|'white'|'lightgreen', layout:'horizontal'|'icon'}` to dynamically choose file.
2. **Tailwind config** – Add `theme.extend.backgroundImage` for hero overlay `url('/assets/brand/lifehouse_color_horizontal.png')`.
3. **Favicon / PWA** – Use `lifehouse_color_vertical.png` @ 32×32, 180×180, 512×512 (generate via real‑favicongenerator).
4. **Email Templates** – Replace `<img src="cid:logo"/>` with `lifehouse_lightgreen_horizontal.png` for light backgrounds.
5. **SEO / OG** – Update `pages/_document.jsx` meta og\:image to `lifehouse_color_large_icon.png` (1200×630).
6. **Dark Mode** – CSS: `.dark .logo-img { content:url('/assets/brand/lifehouse_white_horizontal.png'); }`.

## 6  DEV WORKFLOW (📌 pin in README)

```bash
# 1. Clone & create branch
$ git checkout -b feat/auth-modal

# 2. Add .env
SENDGRID_KEY=...
STRIPE_SECRET=...
OPENAI_KEY=...

# 3. Run dev stack
$ npm run dev

# 4. Run tests
$ npm run test         # Jest
$ npx cypress run      # E2E

# 5. Commit & push
$ git commit -m "feat: signup modal (CR-1)"
$ git push origin feat/auth-modal

# 6. Open PR → request review from QA
```

## 0) SYSTEM ARCHITECTURE (HOW EVERYTHING CONNECTS)

**Monorepo (Replit project)**

* Root folders:

  * `/web` — Public marketing site (Home, About, Programs, Apply, Referrers, Employers, Impact, FAQ, Contact, Donate).
  * `/app` — Secure portal + REST API (single service that serves the SPA + JSON API).
  * `/shared` — Shared assets: validation schemas, constants, i18n keys, RBAC rules, email/SMS templates (text only), and UI copy blocks.
  * `/ops` — DevOps items: backup scripts (no code here, just steps and configs), data retention policy, threat model, runbooks, environment checklist.
  * `/docs` — Architecture map, API contracts, data dictionary, acceptance criteria.

**Runtime connections**

* `web` calls **no API** (marketing only) except:

  * Opens **ConvertKit** modal at your URL for applications.
  * Links to `/app` for logins/portal.
* `app` serves:

  * A **SPA** (portal UI) at `/app/*`.
  * A **REST API** under `/api/*` (same origin—so CORS stays simple).
* **Authentication**

  * Staff SSO: Google & Microsoft via OAuth (free). Callback routes live at `/app/auth/callback/google` and `/app/auth/callback/microsoft`.
  * Residents & Referrers: email+password + TOTP (authenticator app). No paid email required—use on‑screen QR + recovery codes.
* **Storage**

  * **Base option (no external cost):** SQLite (file) in `/data/app.db` with file‑rotation backups to `/backups/`.
  * **Upgrade path (free tier allowed):** Postgres (e.g., Supabase free tier). Keep **SQL‑agnostic** queries and provide a migration plan in `/ops/migrations.md`.
* **AI (OpenAI only)**

  * Single agent with three modes (Notes, Resources, Forms). Calls go server‑side via `/api/ai/*`. Never expose key in the client.
* **Payments**

  * **Phase 1:** “Mail a check / ACH” + pledge form (no fees).
  * **Phase 2 (optional, free to enable):** Stripe in test mode; production only after you decide. Keep it behind a feature flag.

**Environment separation**

* Modes: `DEV` (your Replit draft), `STAGE` (optional), `PROD` (live).
* Each mode has its **own secrets** (Replit Secrets) and **own database file** (or schema).

**Network trust**

* All requests arrive at the `app` server:

  * Public pages: `/app/login`, `/app/forgot` (if enabled).
  * API: `/api/*` protected by JWT (short‑lived) + refresh token (httponly cookie).
  * Admin functions require Admin role + 2FA.

## 1) PRIVACY BOUNDARY (NON‑CLINICAL ONLY)

**Allowed (store/compute)**

* Name, contact info, language, reading level
* Justice status (parole/probation), agent contact info
* Release date, IDs on file (checkboxes), benefits status (Medi‑Cal yes/no only), income range (banded), employment interests
* Attendance (workshops/1‑1), service events (minutes/units), program stage (1–7)
* Resource matches (category, benefit \$\$, eligibility), outcomes (applied/approved/denied)
* House rules acknowledgments, e‑signature (typed, timestamp, IP)
* Maintenance tickets, property details (non‑sensitive)
* Donations (basic donor info + receipt ID)

**Banned (do not store)**

* Diagnoses, treatment plans, prescriptions, detailed SUD or mental health clinical data
* Provider clinical notes, lab results, ICD codes, CPT/HCPCS codes
* Any 42 CFR Part 2 content

**Redaction rules (AI and exports)**

* Strip sensitive free‑text like 3rd‑party names, phone numbers not relevant, pure PHI. Only keep non‑clinical context needed for billing or program reporting.

## 2) ROLES & PERMISSIONS (RBAC MATRIX)

**Roles**

* Resident
* CaseManager
* Intake (Referrals Coordinator)
* Admin (Director)
* Referrer (External)
* Auditor (report‑only)

**Matrix (key actions)**

* Residents: view own profile, stage, attendance summary, saved resources; create tickets tied to their unit; cannot see case notes; can upload consents; can view/download their signed PDFs.
* CaseManager: CRUD residents (assigned), attendance, services, case notes (private by default), run AI drafts, approve AI outputs, generate reports for their caseload, create property tickets.
* Intake: manage referrals queue, run bed/room assignment, launch onboarding flow, assign case manager, generate intake PDFs.
* Admin: everything + user/role management, dictionaries, properties/beds, content blocks, retention actions.
* Referrer: submit referral; view **high‑level** status only (Submitted → Under Review → Accepted/Waitlist/Declined). No resident data access beyond status.
* Auditor: **read‑only** reporting views + exports; no PII beyond what you agree to disclose per contract; downloads watermarked; all access logged.

**Enforcement**

* Every API endpoint checks `role` AND `ownership` (e.g., CM must be assigned to resident or have Admin).
* All exports require Admin or Auditor; scope filters default to **least privilege**.

## 3) DATA MODEL (ENTITY FIELDS, TYPES, INDEXES)

*Note: keep table/collection names consistent; if using SQLite now and Postgres later, avoid vendor‑specific features.*

**User**

* id (uuid, pk, indexed)
* role (enum: Resident | CaseManager | Intake | Admin | Referrer | Auditor, indexed)
* name (text)
* email (lowercased unique index), phone (text)
* language (enum: en | es), readingLevel (enum: resident\_5th | professional)
* auth: passwordHash (nullable for SSO), totpSecret (encrypted), twoFAEnabled (bool)
* ssoProviders (array of {provider, subjectId})
* createdAt, updatedAt (timestamps)
* **Index:** email unique, role

**ResidentProfile**

* id (uuid, pk)
* userId (fk→User)
* dateOfBirth (date) — optional
* justiceStatus (enum: parole | probation | other)
* agentName, agentEmail, agentPhone (text)
* releaseDate (date)
* idOnFile: {stateID (bool), ssn (bool), birthCert (bool), benefitsCard (bool)}
* benefits: {mediCal (bool), calFresh (bool), GA (bool), SSI (bool), otherText}
* incomeBand (enum: none | <1k | 1–2k | 2–4k | 4k+ per month)
* jobInterests (array text), educationLevel (enum)
* driverLicenseStatus (enum: none | expired | valid | inProgress)
* emergencyContact {name, phone, relation}
* consents\[] (array of {type, signedAt, ip, docId})
* goalsSummary (short text, non‑clinical)
* createdAt, updatedAt
* **Index:** userId

**Referral**

* id (uuid, pk)
* source (enum: self | parole | probation | CBO)
* referrerOrg, referrerName, referrerEmail, referrerPhone
* basicResidentInfo {name, email, phone, zip, earliestReadyDate}
* notes (short text)
* status (enum: new | in\_review | accepted | waitlist | declined)
* linkedResidentId (nullable fk→User.id where role=Resident)
* createdAt, updatedAt
* **Index:** status, createdAt

**IntakeChecklist**

* id (uuid, pk)
* residentId (fk→User)
* items\[] (array of {key, label, status: pending|done|na, completedAt, staffId})
* **Standard keys:** id\_copy, medi\_cal\_status, calfresh\_status, bank\_account, phone, clothing, transportation, resume, emergency\_contact, consents\_signed
* createdAt, updatedAt

**ProgramEnrollment**

* id (uuid, pk)
* residentId (fk→User)
* startDate (date), initialTermDays (int=90)
* targetLOS (int days, can be up to 365+ per contract)
* stage (int 1–7)
* stageHistory\[] (array of {stage, at, staffId})
* createdAt, updatedAt
* **Index:** residentId, stage

**Attendance**

* id (uuid, pk)
* residentId, staffId
* date (date), eventType (enum: workshop | one\_on\_one | coaching | check\_in)
* durationMinutes (int)
* notes (short text)
* fundingTag (enum: STOP | ECM | CS | Other) — if relevant
* createdAt
* **Index:** residentId+date

**ServiceEvent**

* id (uuid, pk)
* residentId, staffId
* fundingStream (enum: STOP | ECM | CommunitySupport | Other)
* serviceType (dictionary‑driven: e.g., “life skills class”, “housing navigation”)
* description (short text, non‑clinical)
* units (int: minutes or session count)
* billable (bool)
* attachments\[] (ref IDs to Documents)
* date (date), createdAt
* **Index:** residentId+date, fundingStream

**CaseNote**

* id (uuid, pk)
* residentId, createdBy (staffId)
* noteType (enum: STOP\_progress | ECM\_encounter | Workshop | Coaching | Incident | Other)
* text (long text) — **non‑clinical**
* tags\[] (array text), private (bool default true)
* createdAt
* **Index:** residentId+createdAt

**Resource**

* id (uuid, pk)
* category (enum: housing|food|id\_docs|healthcare|sud\_mh\_referral|employment|training|legal|transport|family|money|emergency|education)
* name, description, eligibility (short), benefitAmount (number, nullable)
* geo {zip, city, county, state}, url, contact
* languages\[] (e.g., en, es)
* status (active | archived), tags\[]
* createdAt, updatedAt
* **Index:** category, status, geo.zip

**ResidentResource (saved resources)**

* id (uuid, pk)
* residentId, resourceId
* status (applied | approved | denied | received | bookmarked)
* notes (short)
* createdAt, updatedAt
* **Unique index:** residentId+resourceId

**Property**

* id (uuid, pk)
* address, city, state, zip
* bedrooms (int), bedsTotal (int), bedsAvailable (int computed), occupancyLimit (int)
* amenities (array text)
* createdAt, updatedAt

**Room**

* id (uuid, pk)
* propertyId, roomNumber
* beds (int), occupants\[] (residentId)
* createdAt, updatedAt
* **Index:** propertyId

**Ticket**

* id (uuid, pk)
* propertyId, roomId (nullable), residentId (nullable)
* category (maintenance | cleaning | it | safety | other)
* priority (low | normal | high | urgent)
* description, photos\[] (doc ids)
* status (new | assigned | in\_progress | on\_hold | resolved)
* assignedTo (staffId), slaDueAt (timestamp)
* timestamps {createdAt, assignedAt, resolvedAt}
* **Indexes:** propertyId, status, priority

**Donation**

* id (uuid, pk)
* donor {name, email}, amount (number), frequency (one\_time | monthly), designation (general | sponsor\_resident)
* receiptId (string), createdAt
* **Index:** createdAt, frequency

**AuditLog**

* id (uuid, pk)
* actorId (nullable for system), action (string)
* entity (string), entityId (string)
* ts (timestamp), ip, userAgent
* beforeHash, afterHash (content digests; store full snapshot only if needed and encrypted)
* **Index:** entity+entityId, ts

**Document**

* id, ownerType (resident | org), ownerId, title, mime, size, storagePath, uploadedAt, checksum

## 4) API CONTRACTS (ENDPOINTS, REQUESTS/RESPONSES, RULES)

**Auth**

* `POST /api/auth/login` — email, password → returns access token (short) + refresh cookie; if 2FA enabled, requires TOTP; rate‑limited.
* `POST /api/auth/enable-2fa` — staff/residents; returns QR data for authenticator apps; stores encrypted secret on approval.
* `POST /api/auth/verify-2fa` — TOTP code to finalize.
* `GET /api/auth/sso/:provider` — redirect to Google/Microsoft.
* `GET /api/auth/callback/:provider` — complete OAuth, issue tokens; create user if first‑time and **not** auto‑assign role (Admin must assign).
* `POST /api/auth/refresh` — rotate token; block if user role changed or account locked.
* **Security rules:** All tokens must be audience/issuer‑checked; refresh cookie is httpOnly, secure, sameSite=strict.

**Referrals & Intake**

* `POST /api/referrals` — public referrer submission; validates spam (honeypot + rate limit); stores with `status=new`.
* `GET /api/referrals?status=` — Intake/Admin only.
* `PATCH /api/referrals/:id` — update status; link to resident.
* `POST /api/intake/:residentId/checklist` — create/update checklist.
* `POST /api/intake/:residentId/assign-bed` — assigns property/room/bed; adjusts occupancy.
* `POST /api/intake/:residentId/consent` — save typed name + timestamp + IP; produce PDF (Document created).

**Residents & Case Management**

* `GET /api/residents?assignedTo=me|id&stage=&query=` — list.
* `GET /api/residents/:id` — Resident 360 (filtered by role).
* `POST /api/attendance` — create; `GET /api/attendance?residentId=&dateRange=`
* `POST /api/services` — log service; `GET /api/services?...`
* `POST /api/casenotes` — create; private by default; `GET /api/casenotes?residentId=` (CaseManager/Admin only)

**Resources**

* `GET /api/resources?category=&zip=&benefitMin=&language=&status=active` — public.
* `POST /api/resources` — Admin/Intake/CM (curation).
* `POST /api/resident-resources` — save resource to resident; set status.
* `GET /api/resident-resources?residentId=`

**Properties & Tickets**

* `GET /api/properties` — Admin/Intake/CM.
* `POST /api/tickets` — create from resident or staff.
* `PATCH /api/tickets/:id` — status changes, assignments, SLA updates.
* `GET /api/tickets?propertyId=&status=&assignee=`

**Reporting & Exports**

* `GET /api/reports/stop/monthly?month=YYYY-MM` — CSV + PDF cover; Admin/Auditor only.
* `GET /api/reports/ecm/monthly?month=YYYY-MM`
* `GET /api/reports/attendance?residentId=&range=`
* `GET /api/reports/donations?range=`

**AI (server‑side only)**

* `POST /api/ai/draft-note` — input: residentId, noteType, bullet points → output: structured note text + 1–2 sentence rationale; **requires CM approval**.
* `POST /api/ai/recommend-resources` — input: residentId, zip, categories → output: 5 internal resources w/ eligibility reasons.
* `POST /api/ai/form-helper` — input: form context + known resident fields → output: autofill suggestions + “missing fields” list.
* **Guardrails:** Reject if prompt contains clinical keywords or suggests storing PHI; log all AI calls (actor, purpose, token count).

**Audit**

* All **mutations** log to `AuditLog` with digest of before/after; exports log a “downloaded\_by” event with file hash.

## 6) AI ASSISTANT (PROMPT LOGIC, MODES, GUARDRAILS)

**Modes**

1. **Note Draft** — Input: bullets (what happened, minutes, goals addressed), context (resident stage, event type). Output: structured, contract‑friendly note (STOP or ECM style) + **1–2 sentence reason** for changes/suggestions. Flag if clinical phrases are seen → require edit.
2. **Resource Recommender** — Input: resident zip, category filters, profile goals; searches **internal** `Resource` list only; Output: 5 items with eligibility rationale and expected benefit amount if stored.
3. **Form Helper** — Input: intake/service form schema + resident known fields; Output: suggested autofill fields + “missing required” list; never fabricates.

**Guardrails**

* Block outbound web search (to avoid scraping costs and privacy risks).
* Redact extraneous names; avoid PHI terms.
* Add banner “AI draft—human review required” on any AI output.
* Log: actorId, purpose, tokens used, latency; display to Admin for cost oversight.

## 8) SECURITY & DEVOPS (HARD REQUIREMENTS)

**Authentication**

* Staff: SSO only + TOTP enforced every login (no “remember me”).
* Residents/Referrers: email+password + TOTP optional for referrer (encouraged).

**Authorization**

* Enforce per‑endpoint RBAC and **ownership checks**.
* Deny by default; allow minimal scopes.

**Transport**

* HTTPS only; HSTS; strict CSP (no inline scripts), Referrer‑Policy: strict‑origin‑when‑cross‑origin.

**Storage**

* Encrypt at rest: TOTP secrets, consent signatures, emergency contact, recovery codes.
* Hash passwords using slow hash (configurable work factor).
* Daily encrypted backup of DB file to `/backups/` (retention 30 days) with a **restore drill** doc in `/ops/runbooks.md`.

**Logging**

* App log (rotated), AuditLog table (all auth events, CRUD, exports, AI calls).
* PII in logs: **No**. Use IDs only.
* Alerting: if free email is unstable in Replit, write a “critical events” dashboard tile in Admin Console.

**Rate limiting & abuse**

* Public endpoints (referrals, login): IP+fingerprint rate limits (e.g., 10/min burst).
* Abuse ban list: if repeated spam, put IP/email on deny list (config file).

**Retention**

* 7 years for resident records; hard‑delete only by Admin with dual confirmation; log deletion in AuditLog with digest.
